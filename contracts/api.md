# API contract

Served by **backend/**, consumed by **web/**. Changes only via PR reviewed by
all three members.

- Source of truth in code: `backend/app/schemas/api.py` (pydantic, `extra="forbid"`),
  mirrored by `web/src/types/api.ts`. `backend/tests/test_contracts.py` fails if a
  fixture drifts from the models.
- Base path `/api`. JSON, UTF-8 (CSV for `/api/export`). Errors: FastAPI default
  `{"detail": ...}`; `404` unknown id, `422` invalid input.
- Ids are validated: `law_id` `^[a-z0-9]+(-[a-z0-9]+)*$`, `article_id`
  `{law_id}:{number}` with `number` `^\d+(\.\d+)*$`. Nothing from the client
  reaches Cypher except as a parameter.

## Modes and fixtures

| mode | data | graph |
|---|---|---|
| `MOCK=1` (default) | `contracts/fixtures/processed/` — the invented **[ЖИШЭЭ]** sample dataset | in memory, no Neo4j / LLM / network |
| `MOCK=0`, `GRAPH_BACKEND=neo4j` | `data/processed/` loaded into Neo4j | Cypher |
| `MOCK=0`, `GRAPH_BACKEND=memory` | `data/processed/` | in memory |

With `MOCK=1` every endpoint is computed from the sample dataset by the same
services that run on Neo4j, so every id works (not just the ones in fixtures).
Responses carry the header `X-LawLens-Sample: true`.
`contracts/fixtures/<name>.json` = `{"_sample": true, "_note", "endpoint",
"request": {"query", "body"}, "response"}` is a recorded example for every
endpoint, regenerated by `python scripts/seed_demo.py`;
`backend/tests/test_api_mock.py` replays each request and requires an identical
response. `backend/tests/test_neo4j.py` requires the Neo4j store to give the same
answers as the in-memory store.

## Reliability rules (apply to every result)

1. Every item cites **law + provision + link**: `law_id`, `law_name`, `number`,
   `source_url` (`url` for international sources).
2. `type: "fact"` = deterministic (regex citation in the text), `confidence: 1.0`.
   `type: "suggestion"` = embeddings or an LLM, `confidence` in 0..1 and `model` set.
   The UI shows them separated: "Баримт" vs "Санал, 82%".
3. Suggestions carry an `explanation`. Wording never states a legal verdict.
4. Impact analysis is hypothetical: nothing is written to the graph.

## Common types

```ts
RefItem {
  law_id: string, law_name: string,
  article_id: string | null,     // null when the provision does not exist or its law has no text
  number: string | null,         // null when the whole law is meant
  snippet: string,               // provision excerpt (or the citation text)
  source_url: string,
  type: "fact" | "suggestion",
  confidence: number,            // 0..1; facts are 1.0
  flags: { uses_old_name: boolean, target_missing: boolean },
  anchor_number?: string | null, // provision number on the SELECTED side
  score?: number | null,         // similarity score
  explanation?: string | null,   // reason, in Mongolian
  // v0.2, additive:
  raw_text?: string | null,      // exact citation text, e.g. "Хөдөлмөр хамгааллын тухай хуулийн 12.1-д"
  matched_name?: string | null,  // law name as cited (former name when uses_old_name)
  cited_number?: string | null,  // provision number exactly as cited
  current_number?: string | null,// new number from a renumbering table when target_missing
  model?: string | null          // suggestions: model that produced them
}
LawGroup { law_id: string, law_name: string, count: number, items: RefItem[] }
```

A `RefItem` always describes the *other* provision. `LawGroup.count ==
items.length`; groups are sorted by `count` desc.

### GET /api/laws?q=

`q` matches (case-insensitive, whitespace-normalised substring) current,
**former** and short names.

```json
[{"law_id": "khodolmoriin-tukhai-khuuli", "name": "Хөдөлмөрийн тухай хууль", "former_names": [],
  "article_count": 17, "short_names": [], "text_available": true,
  "source_url": "https://example.org/lawlens-sample/laws/khodolmoriin-tukhai-khuuli"}]
```

`text_available: false` = the law is known only by name (cited, text not loaded).

### GET /api/laws/{law_id}

```json
{"law": {"law_id": "...", "name": "...", "former_names": [], "short_names": [],
         "adopted_date": "2021-07-02", "source_url": "...", "text_available": true},
 "articles": [{"article_id": "...:80", "number": "80", "title": "Ажлын цаг", "text": "", "parent_number": null},
              {"article_id": "...:80.1", "number": "80.1", "title": null, "text": "...", "parent_number": "80"}]}
```

`/articles` returns only the `articles` array.

### Connections — `GET /api/articles/{article_id}/connections`, `GET /api/laws/{law_id}/connections`

Selecting an article covers the provision **and everything under it**
(`80` covers `80.1`, `80.1.2`, ...); `anchor_number` names the exact provision.
A law-level selection lists only links to *other* laws.

| key | UI section | content |
|---|---|---|
| incoming | 1. Үүнийг иш татсан | facts: provisions citing the selection (incl. citations of numbers under it that no longer exist), grouped by citing law |
| outgoing | 2. Үүнээс иш татсан | facts: provisions / laws the selection cites, grouped by cited law |
| former_name_refs | 3. Хуучин нэр / дугаар | subset of incoming ∪ outgoing with `flags.uses_old_name` |
| missing_target_refs | 4. Заалт олдсонгүй | subset of incoming ∪ outgoing with `flags.target_missing` |
| similar | 5. Ижил асуудлыг зохицуулсан | `RefItem[]` suggestions with `score`, no direct citation between the pair |
| overlaps | 6. Болзошгүй давхардал | `RefItem[]` suggestions from relations `kind:"overlap"` *(v0.2)* |
| conflicts | 7. Болзошгүй зөрчил | `RefItem[]` suggestions from relations `kind:"conflict"` |
| totals | | `{incoming, outgoing, former_name_refs, missing_target_refs, similar, conflicts, overlaps}` |

Section 8 (Олон улсын эх сурвалж) is `GET /api/articles/{id}/international`.
`ArticleConnections` adds `article: {article_id, number, title, text, parent_number, law_id, law_name, source_url}`.

### Impact — `POST /api/impact`, `POST /api/articles/{article_id}/impact`

```json
POST /api/impact
{"article_id": "khodolmoriin-tukhai-khuuli:80.1", "new_text": "...", "depth": 2}
{"law_id": "khodolmor-erkhleltiig-demjikh-tukhai-khuuli", "new_name": "...", "depth": 2}
{"article_id": "khodolmoriin-tukhai-khuuli:80.1", "new_number": "81.1", "depth": 1}

POST /api/articles/{article_id}/impact
{"new_text": "...", "new_name": null, "new_number": null, "depth": 2}
```

At least one of `law_id` / `article_id`; `depth` 1..3 (default 1 on
`/api/impact`, 2 on the article endpoints); `new_number` must look like `81.1`.

- **text change** (`new_text`, or nothing): depth 1 = provisions citing the
  provision or the article/part that contains it.
- **renumber** (`new_number`): the provision and everything under it; depth-1
  items get `flags.target_missing = true` (their citation would no longer resolve).
- **rename** (`new_name`, law-level): every citation of the law by name from
  other laws; depth-1 items get `flags.uses_old_name = true`.
- depth *n* = provisions citing a depth *n-1* provision (or its containing
  article/part). A provision appears once, at its smallest depth.
- `new_similar` = provisions of other laws similar to `new_text` (suggestions).

```json
{"depths": [{"depth": 1, "count": 4, "groups": [LawGroup]}, {"depth": 2, "count": 2, "groups": [LawGroup]}],
 "new_similar": [RefItem],
 "totals": {"laws": 4, "articles": 6, "new_similar": 1, "direct": 4, "indirect": 2},
 "direct_impact": [LawGroup],          // = depths[0].groups           (v0.2)
 "indirect_impact": [LawGroup],        // depths[1:] flattened          (v0.2)
 "change": {"kind": "text", "law_id": "...", "law_name": "...", "article_id": "...", "number": "80.1",
            "summary": "Хөдөлмөрийн тухай хуулийн 80.1 заалтын бичвэрийг өөрчлөх"},
 "note": "Энэ нь түр тооцоолол бөгөөд хуульд өөрчлөлт оруулахгүй."}
```

`GET /api/articles/{id}/impact?depth=2` = the same with no change (what depends on the provision).

### Drafts

`GET /api/drafts` → `Draft[]` (same fields as `drafts.json`, see data-format.md):
`{draft_id, lawforum_id, title, target_law_id, new_name, amended_article_ids[],
cosubmitted_law_ids[], source_url, operations: DraftOp[], cosubmitted_titles[]}`.
`DraftOp = {op: replace|insert|delete|repeal|add|rename, law_id, number, article_id,
old_text, new_text, raw_text, uses_old_name, target_missing}` — parsed from the bill
text ("…гэснийг …гэж өөрчилсүгэй" etc.), i.e. facts.

`GET /api/drafts/{id}/gaps` (alias `/gap`): laws whose provisions cite a provision the
bill amends (or the law it renames), outside the bill's target law:

```json
{"draft_id": "draft-sample-labor-001", "found": 3,
 "covered": [LawGroup],   // in the co-submitted package  -> "Тусгагдсан"
 "missing": [LawGroup],   // not in the package          -> "Орхигдсон"
 "review":  [LawGroup]}   // reached only at depth 2      -> "Шалгах шаардлагатай"   (v0.2)
```

`found` = number of laws in covered + missing. Items explain the citation that makes
the law expected. This is a checking aid, not a statement that an amendment is required.

`GET /api/drafts/{id}` → `DraftDetail {draft, target_law: LawSummary, amended: [{op, article: ArticleDetail|null}],
cosubmitted: LawSummary[], gap: DraftGap}`.

### International — `GET /api/articles/{article_id}/international`

```json
{"article_id": "...",
 "foreign_laws": [IntlItem], "treaties": [IntlItem]}
IntlItem {source_id, kind: "foreign_law"|"treaty", country_or_org, title, url,
          summary, relevance, explanation, type: "suggestion",
          provision, model, anchor_number}          // last three: v0.2
```

Mapping to the requested source fields: title → `title`, country/organization →
`country_or_org`, provision → `provision`, source_url → `url`, relevance →
`relevance`, explanation → `explanation`.

### Amendment suggestion — `GET /api/articles/{article_id}/amendment`

```json
{"article_id": "...", "suggested_text": "...", "reason": "...",
 "sources": [{"kind": "law_article"|"foreign_law"|"treaty", "id": "...", "title": "...", "url": "..."}],
 "type": "suggestion", "confidence": 0.68, "model": "demo-llm"}
```

### Relation detail — `GET /api/articles/{a}/relations/{b}` *(v0.2)*

Side-by-side view of an overlap / conflict suggestion between two provisions:
`{a: ArticleDetail, b: ArticleDetail, kind, type: "suggestion", confidence,
explanation, model, score, international: IntlItem[], resolution: Amendment | null}`.

### Search — `GET /api/search?q=` *(v0.2)*

Law names (current, former, short), provision numbers and keywords; Mongolian
case endings are stemmed ("цалингийн" finds "цалин").

```json
{"query": "ажлын цаг",
 "laws": [LawSummary],
 "articles": [{"article_id", "law_id", "law_name", "number", "title", "snippet", "source_url"}]}
```

### CSV — `GET /api/export` *(v0.2)*

| `kind` | required params |
|---|---|
| `connections` | `article_id` |
| `law_connections` | `law_id` |
| `impact` | `article_id` or `law_id`; optional `new_text`, `new_name`, `new_number`, `depth` |
| `draft_gap` | `draft_id` |
| `international` | `article_id` |
| `search` | `q` |

Optional `list` keeps one list: `incoming`, `outgoing`, `former_name_refs`,
`missing_target_refs`, `similar`, `overlaps`, `conflicts`, `depth1`, `depth2`,
`depth3`, `new_similar`, `covered`, `missing`, `review`, `international`, `search`.

UTF-8 with BOM, CRLF. Columns: `law_name, provision_number, relationship, type,
label, confidence, flags, source_url, anchor_number, explanation, model, snippet`
(`label` = "Баримт" / "Санал, 82%", `flags` = "Хуучин нэр; Заалт олдсонгүй").
